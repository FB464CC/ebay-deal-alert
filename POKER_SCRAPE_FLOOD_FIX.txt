## 2026-09-10 — decision from the evidence

- A fixed 45-minute post-surge slice (`19:43Z`–`20:28Z`) has 281 poker rows
  (258 `NO_AI_BUDGET`, 7 checked, 0 delivered) and 57 golf-equipment rows
  (7 `NO_AI_BUDGET`, 25 checked). Across the fresh log, golf scrape has
  54 checked rows and 16 `NO_AI_BUDGET` rows. This refutes a claim that golf
  has a reliably idle share to trim.
- The golf/poker values are *soft allocation shares*, not spend reservations:
  unused shared slots backfill. Reducing golf's soft cap would not pay for a
  second isolated scrape call. Raising `EBAY_SCRAPE_AI_CHECK_LIMIT` would add
  a possible paid call, while the ledger is already full, so it is not
  justified.
- The supported cost-neutral/non-increasing fix is instead to route poker
  scrape candidates through poker's already-configured two-slot shared share,
  exactly like the existing golf exception. That changes no numeric cap and
  cannot add a paid call: poker now displaces a shared candidate, while the
  one isolated scrape call remains available only to another scrape category.
  (If no such category is present, actual calls can be lower.) It makes
  poker's existing reservation reachable rather than adding capacity.
- Fresh title-level evidence also supports a narrow pre-AI ranking signal,
  not a rejection: recent isolated picks were an acrylic carry case, a
  `Deluxe ... 300 Bulk Full Clay` sample (vision: ABS/stickers, visible count
  10), and a rotating chip carousel (vision: ABS, visible count 8). The
  title's bare `clay` and `300` claims were therefore not treated as proof.
  The implementation will only rank evidence-shaped >=100-chip maker/set
  language ahead of obvious accessory/sample/novelty language, retaining all
  rows for later retry.
- Fresh duplicate check found zero duplicate item IDs and zero normalized
  title+price pairs within each of 60 poker-scrape query/run groups (and the
  eight 50–81-row combined runs). No speculative title+price dedup will be
  added. Cross-run recurrence is real but is a different problem.
