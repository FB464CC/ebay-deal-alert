  `conditionId` fields on Browse item objects and warns that display names may

  wire shape: `"condition":"Pre-owned - Good","conditionId":"3000"`.
- The live eBay search surface currently returns known broken Hamilton watches
  with the displayed structured condition "Parts Only" (for example legacy

  addition to the canonical 7000 label.
- eBay's current category-condition help also documents "Damaged" as a
  non-operable tire condition and discusses salvage condition descriptors;
  these category-varying nonfunctional labels should be defensive text
  backstops, while ID 7000 remains the authoritative general hard fail.
- No EBAY_CLIENT_ID/EBAY_CLIENT_SECRET environment variables or token-cache
  file exist in this checkout. A real request to the production Browse search
  endpoint without credentials returned HTTP 403, consistent with eBay's

  environment. The official docs, locally captured real Browse JSON, current
  public eBay search results, and production alert record provide the closest
  available evidence without inventing credentials.
- The production pipeline cannot recover the exact description after the fact:
  `item_summary/search` does not provide it; the code optionally spends a

  description endpoint now returns HTTP 410 for the ended/removed listing.
  Since the delivered alert passed the later description re-check too, the
  fetched description was either absent/unavailable or did not contain an
  existing hard-fail phrase. In either case, a text-only gate was structurally
  insufficient for the already-present structured condition.

Progress 3 - implementation and focused regression validation
- Replaced the broad `conditions:{USED|UNSPECIFIED}` filter in both
  `search_ebay()` and `search_ebay_ending_soon_auctions()` with a shared
  positive `conditionIds` allowlist of documented non-new conditions 2000,
  2010, 2020, 2030, 2500, 2750, 2990, 3000, 3010, 4000, 5000, and 6000.
  Explicitly nonfunctional ID 7000 is absent.
- `_ebay_items_from_body()` now copies each item_summary's existing
  `condition` / `conditionId` values to stable `ebay_condition` /
  `ebay_condition_id` listing keys. Both regular and auction search lanes use
  this common parser, so no extra API request is involved.
- Added an authoritative client-side hard fail for conditionId 7000, plus
  category/display-name backstops for For Parts, Parts Only, Not Working,
  Non-working, Nonfunctional, Damaged, Salvage, and Restoration Required.
- Applied that hard fail before brand/AI/valuation work in `score_listing()`
  and again at the start of `is_blocked_by_steal_quality_gate()`, so an
  upstream merge/reordering cannot turn an explicit nonfunctional condition
  back into an alert.
- Condition evidence is now persisted in alert-log records as
  `ebay_condition` and `ebay_condition_id`, making future production
  rejections auditable instead of losing the raw structured fields.
- Added regression coverage for the exact neutral Hamilton title through:
  (1) the existing description-keyword mechanism, (2) structured condition
  text with no warning in title/description, (3) conditionId 7000, (4) both
  regular and ending-soon Browse lanes, (5) the final quality-gate backstop,
  and (6) a full `run()` integration assertion proving zero AI calls and zero
  delivered alerts. Also covered working used ID 3000 as a non-rejection.
