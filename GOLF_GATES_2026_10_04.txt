TASK 2 - ERA GATE (completed and checkpointed)
================================================

Implementation
--------------
- Extended golf-equipment.full_set_vintage_model_patterns with researched,
  name-bounded pre-2012 families. The gate searches seller title/description;
  it does not invent an age from styling or an unidentified brand.
- Added generic era wording: Classic, Retro, 90s/1990's, 80s, Antique. The
  Classic regex explicitly exempts the prose phrases "classic fit" and
  "classic condition". The rule only runs inside the golf profile, so it is
  golf-context scoped. Existing Vintage/VTG rules remain unchanged.
- Added a second evidence path for vision output. The production golf prompt
  already requests identified_model and model_release_year, the merge already
  stores them as golf_identified_model/golf_model_release_year, and the alert
  log already persists them. The new veto requires BOTH a nonblank identified
  model and a finite integral numeric year below 2012. Missing, boolean,
  fractional, or string years fail open.
- Tightened the prompt's meaning without adding a call or field: whenever
  irons are present, identified_model/model_release_year must describe the
  coherent iron line, never a driver/wood/hybrid/putter/bag; mixed or unreadable
  iron lines must return null. This prevents the exact Task-1 failure where the
  delivered assorted lot's 2016 M2 DRIVER made Pinnacle irons look modern.
- Historical availability is sparse but usable: 139 of 4,517 AI-checked golf
  rows carry both fields; 100 distinct rows say pre-2012. Spot checks line up
  with named releases (for example Eye2=1982 and Zing=1992). The rule is used
  as a negative veto only, never as proof that an otherwise incoherent set is
  modern. Seventeen rows that escaped both the old gate and every newly named
  regex are newly stopped specifically by the structured AI year.

TASK 5 - SELLER TRUST / PHOTO CONTRADICTION (completed and checkpointed)
=======================================================================

Seller fields actually present in normalized listing dictionaries
-----------------------------------------------------------------
- Official eBay Browse API: item summaries expose seller.feedbackScore and
  seller.feedbackPercentage. Both the ordinary Browse search and the official
  auction lane call _attach_seller_feedback(), which flattens those values to
  seller_feedback_score and seller_feedback_percentage on the listing/result.
  This is the only current golf source with a true feedback-count field.
- eBay HTML scrape: the parser extracts item id, title, price, image, and
  auction timing/bid count. It does not extract seller identity, rating, or
  feedback. Its platform is explicitly ebay_scraped, so it fails open.
- ShopGoodwill: the search response provides sellerName/sellerId (the Goodwill
  store identity), which is normalized only as seller.username. No feedback
  count or rating is present in the listing dictionary, so it fails open.
- Facebook/Scout: the accepted queue schema carries platform, item id, title,
  price, URL, optional image/description, discovery time, and search routing.
  It has no seller or feedback field, so it fails open.
- Other normalized adapters, although not productive golf lanes in this
  history: Poshmark and Vinted retain a seller identifier but no feedback
  count; OfferUp and Depop retain none. Grailed exposes seller_trusted,
  seller_rating, and seller_total_sales, but total transactions are not the
  same fact as a zero feedbackScore and no golf search currently routes there.
  No zero-feedback inference is made from any of those different fields.

Implementation
--------------
- Added golf_zero_feedback_seller_reason() before the golf price paths. It
  rejects only a finite numeric feedbackScore exactly equal to zero on the
  official eBay path. A missing value, malformed/string value, boolean, HTML-
  scraped eBay row, or any non-eBay platform fails open.
- Persisted seller_feedback_score/percentage in future alert-log rows so this
  rule can be audited rather than disappearing after dispatch. All 60
  historical delivered rows predate that serialization and omit both fields;
  none is retroactively classified as a zero-feedback seller.
- Focused verification: 4 tests / 6 subtests pass, including official zero,
  missing/malformed fields, ebay_scraped, and ShopGoodwill controls.

Photo-count contradiction audit
-------------------------------
- The golf prompt requests clubs_identified as one free-form string. Examples
  range from a parseable-looking phrase such as "5 mixed-brand irons" to
  uncounted prose such as "mixed clubs, bag, and range balls". There is no
  structured visible_iron_count field, no per-club array, no confidence flag,
  and clubs_identified is not merged into the result or historical log.
- Therefore the retained historical rows cannot establish that a number in
  that prose is photo-derived, complete, or comparable with a title range.
  Implementing a numeric veto would guess from an unvalidated sentence and
  could block a clean set whose gallery hid one club. Per the owner's explicit
  instruction, no speculative photo-count veto was implemented. The existing
  AI playability/incoherent-grab-bag verdict remains enforced, but it is not
  represented as a precise title-versus-photo count check.

Backtest result
---------------
- Newly blocked historical rows: zero can be proven, because feedback was not
  serialized on the reconstructed rows. Missing evidence is deliberately not
  converted to zero.
- Clean modern sets newly blocked: zero. Only a future official eBay listing
  carrying an actual numeric feedbackScore=0 is newly rejected; every platform
  or row without that fact remains eligible.
