Checkpoint 5 - conservative implementation and correctness guardrails
- Added numeric config only: `GEMINI_BATCH_SIZE=3` and `GEMINI_BATCH_MAX_RAW_IMAGE_BYTES=12000000`. A byte ceiling well below the documented 20 MB inline-request cap prevents an unexpectedly image-heavy group from being sent. All pre-existing config values, every saved search, and `AI_PAID_MONTHLY_BUDGET_USD=10` are byte-for-value unchanged after JSON comparison with HEAD.
- Refactored the existing Gemini credential-pool request loop into a shared parts sender without changing its key selection, rotation, cooldown, quota classification, or retry behavior. A single-candidate call remains the existing request shape; a batch is merely another synchronous parts request routed through that same pool.
- Batching is enabled only when DeepSeek remains the configured primary, the paid vision lane is already exhausted at run start, and at least two eligible Gemini-fallback candidates can be prepared. If paid capacity exists, each DeepSeek paid-primary call remains one candidate/request. Ending-auction and isolated one-slot lanes remain unbatched. Candidate counters and per-run fairness still count outcomes, not HTTP requests.
- Each batch request uses explicit `BEGIN/END CANDIDATE <ID>` and image-boundary markers. The structured-output schema requires one result object per requested ID, but application code independently validates IDs. Results map by exact ID, never array position; reordering is safe, unexpected IDs are ignored, and missing, malformed, non-object, or duplicate entries fail closed only for the affected candidate. Valid siblings can continue. A wholly malformed/network-failed batch fails closed for all members so none can receive another listing's verdict.
- Candidate lookahead does not bypass existing gates: a future eBay candidate performs its already-required detail fetch and the same late hard-fail helper before entering a batch. The attempt is marked so it is not fetched twice on its normal turn. Candidates terminal on condition/size/text/evidence gates are never sent merely to fill a batch. Prepared images are reused, avoiding duplicate downloads.
- No monthly category-dollar throttle was added. The code audit confirms the existing mechanism is per-run soft fairness rather than monthly-dollar fairness, so the semantic gap is real. But the corrected evidence proves only a 40.37% largest recoverable category and leaves 53.64% unattributable. Per the requested evidence threshold, inventing a category percentage from that record would be less honest than retaining the global $10 hard cap and the existing golf/poker soft reservations unchanged.
