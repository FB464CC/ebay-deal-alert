Confirmed findings (before implementation)
------------------------------------------

F1 - Weekly digest multiplies production discounts by 100 (analytics bug).
     `compute_deal_rating()` returns and `append_alert_log()` persists whole
     percentage points (for example 80 means 80%). The current retained log has
     123 numeric discount_pct values ranging from -1746 through 88, confirming
     the production unit. `send_weekly_digest()` instead uses the `.0%` ratio
     formatter for "Biggest verified discount" and every "Top delivered deal",
     so a stored 80 is rendered as 8000%. Existing digest tests use 0.80-shaped
     fixtures even though the production writer stores 80, masking the defect.

F2 - A quiet-hours queue write failure causes duplicate notifications.
     After a queued alert is delivered, `flush_quiet_alert_queue()` marks the
     item seen but ignores a false return from the atomic queue rewrite. On the
     next flush it sends the still-present queue row without consulting the
     seen table. A temporary-file reproduction forced the queue save to fail:
     two consecutive flushes both returned 1 and `send_alert()` was called
     twice even though `is_new()` was already false after the first delivery.
     This path also uses only one seen-marker attempt, unlike the normal
     delivery path's three attempts and loud health alert.

F3 - A stalled Facebook GET wedges every extension scan indefinitely.
     The ingest POST already has a 20-second AbortController, but
     `scanFacebookTargetViaFetch()` has no timeout. `runScan()` serializes all
     targets and coalesces later alarms into the existing `runningPromise`, so
     one never-settling fetch blocks the remaining targets and every later
     alarm until Chrome kills/restarts the worker. A Node reproduction with an
     unresolved fetch remained pending; there is no internal escape path.

F4 - Cache pruning is allowed to destroy the last good dedupe snapshot after
     a failed cache save. The workflow's save and prune steps both use bare
     `if: always()`. If actions/cache/save fails, prune still deletes every
     prior `seen-items-db-v1-*` key except the new key that was never created.
     The next run then falls back to the stale git seed (phase 1) or fails
     closed (phase 2). Pruning must be conditional on confirmed save success.

F5 - The Telegram analysis webhook retains the same paid DeepSeek waste that
     was just removed from the main poller. Its request has no timeout, omits
     the explicit thinking-disable control, and permits 8,192 output tokens
     for both compact JSON and a 2-4 sentence follow-up. A harness confirmed
     the emitted payload is max_tokens=8192, has no thinking control, and has
     no abort signal. In addition, up to four 12-second image downloads run
     serially before that unbounded call inside a 60-second serverless route.
     Independent image fetches can safely run concurrently; output ceilings
     should match the already-settled 2,048 vision / 512 text limits.

F6 - Operator documentation contradicts deployed behavior.
     The root README says the workflow commits `seen_items.db`, says the
     AI ledger is inside that DB, and advertises an $18 default; production
     now caches seen_items.db, commits ai_spend.db separately, and config fixes
     the user's ceiling at $10. The extension README says there are eight golf
     targets, while the shipped code has nine golf plus six poker targets.

F7 - `_get_ebay_token_uncached()` is unreachable duplicate OAuth code.
     Repository-wide reference search finds only its definition. The active
     `get_ebay_token()` implements the same request plus caching and bounded
     retries. Retaining the duplicate creates a second, stale auth contract
     that tests and production never exercise.

F8 - The new MONTHLY_BUDGET_EXHAUSTED disposition is bypassed by every
     category that has its own no-AI gate. PASS 3 computes `gate_reason`
     first; watches, golf equipment, poker chips, knitwear, and several
     scoped bars return a retryable "no AI price" reason. The exhaustion
     annotation is guarded by `if not gate_reason and ai_result is None`, so
     it runs only when no category reason exists. Current production evidence
     matches the trace: the retained schema-v4 log has 127 NO_AI_BUDGET rows
     and zero MONTHLY_BUDGET_EXHAUSTED rows, including post-cap watch/golf
     rows with none of the new cap/reset fields. A new end-to-end watch test
     reproduced the defect before the fix: expected MONTHLY_BUDGET_EXHAUSTED,
     actually received NO_AI_BUDGET. The correction must override only a
     retryable no-AI reason, never an unrelated permanent category rejection.

F9 - A partial mirrored exhaustion-notification claim suppresses the outage
     warning forever. The notifier commits its claim to ai_spend.db and
     seen_items.db sequentially, but its persistence exception path did not
     undo an earlier successful commit. On the next run, the surviving first
     claim is interpreted as proof that the ntfy warning was already sent,
     even though sending occurs only after both commits. A SQLite trigger that
     rejects the second insert reproduced this: the first invocation returned
     without notifying and every later invocation remained suppressed after
     the database recovered. This is specifically the self-healing warning
     path added by the latest budget work, not a change to its $10 policy.

Implemented fixes and focused verification
------------------------------------------

- Weekly digest ranking and display now normalize both current whole-percent
  values and legacy fractional values. Added a mixed-unit regression proving
  0.90 ranks above 80 and renders as 90% / 80%, never 8000%.
- Quiet-hours flush now checks durable seen state before sending, retries its
  post-delivery seen marker three times, emits a health alert on persistent
  bookkeeping failure, and reports queue-cleanup failure. Added a regression
  that forces both cleanup writes to fail and proves two flushes produce one
  external send, not two.
- Facebook background fetches now abort after 20 seconds (including a stalled
  response body), so one target cannot wedge the serialized scanner. A Node
  test drives the timeout at 5ms and confirms both abort state and diagnostic.
- Cache prune now depends on the preceding save step's successful outcome.
  A workflow contract test locks the state-safety dependency in place.
- Telegram DeepSeek calls explicitly disable thinking, use 2,048-token JSON /
  512-token text ceilings, and abort after 30 seconds. The four independent
  image downloads now start concurrently under the same four-image cap.
  Node-backed tests inspect both request modes and prove all four downloads
  start before any settles.
- Added a configuration contract test proving every one of the extension's
  nine golf and six poker defaults maps to exactly one enabled Facebook saved
  search with the expected category.
- Monthly exhaustion now overrides category-specific retryable no-AI reasons,
  attaches the cap/reset metadata, and preserves the intended retryable seen
  state. An end-to-end watch-category run now records
  MONTHLY_BUDGET_EXHAUSTED; permanent category rejections are not overridden.
- A failed second-database exhaustion-notification claim now releases any
  first-database commit before returning. A fault-injection regression proves
  that once the mirror recovers, the next run sends exactly one warning and
  persists the durable claim to both ledgers.
- Removed the unreachable duplicate OAuth helper and corrected the root and
  extension READMEs (plus stale test rationale) to describe the actual
  persistence, budget, and targets.
- Removed the repository-owned invalid-escape SyntaxWarning by making the two
  regex-heavy test docstrings raw strings. The remaining lxml warnings arise
  inside the installed dependency's deprecated no-op `strip_cdata` option.

Risks deliberately flagged rather than guessed at
--------------------------------------------------

- The Facebook Marketplace DOM could not be re-verified in a live authenticated
  Chrome session from this checkout. Its parser remains covered by captured DOM
  shapes and extraction tests, and target/config parity is now enforced, but an
  authenticated manual Scan Now remains the right deployment smoke test.
- Telegram's separate serverless DeepSeek path is not part of the poller's
  mirrored $10 SQLite ledger. Token/time waste was removed here, but enforcing a
  cross-runtime dollar cap needs a shared authoritative store or a provider-side
  cap; inventing a second local counter would not be safe. This limitation is now
  explicit in README.md.
- `telegramSend()` neither times out nor checks Telegram's HTTP status. A naive
  throw-on-error change can turn webhook retries into duplicate paid AI calls;
  correcting this safely requires update-id idempotency before changing delivery
  error semantics. It is left as an explicit follow-up, not silently papered over.
- The workflow still carries its documented phase-1 tracked seen_items.db seed.
  Removing that seed is an operational migration: first confirm a healthy recent
  cache exists, then untrack it and remove the temporary checkout-discard line.
- The local checkout is shallow and does not contain brief-referenced commit
  1ae0244, so claims about that missing patch are based on the retained repository
  investigation reports and current code, not an unavailable git diff.
