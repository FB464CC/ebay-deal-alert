Checkpoint A2 - full function-by-function audit and fixes
- Read all 11,276 lines of ebay_deal_alert.py in function order, including the
  complete run() collection/prioritization/AI/delivery pipeline. Searched the
  full file for TODO/FIXME/XXX markers; none are present.
- Fixed a real 429-recovery crash in `_trip_ebay_circuit_breaker()`. Its state
  reader correctly allowed any JSON object, but the trip path blindly did
  `state.get("consecutive_429_streak", 0) + 1`. A JSON-valid persisted value
  such as `"bad"` raised TypeError while handling an actual 429, interrupting
  the very recovery path meant to protect eBay. Invalid/non-finite/negative
  values now reset to zero before incrementing. The regression supplies the
  formerly crashing state and proves a fresh, valid backoff is persisted.
- Fixed four JSON-valid wrong-shape state crashes. `_read_cached_ebay_token()`
  called `.get()` on a list/scalar; `load_quiet_alert_queue()` did the same
  before its advertised legacy-list fallback could execute;
  `load_search_activity()` called `.get()` on non-object JSON; and
  `_weekly_ai_spend()` called `.get()` on a non-object digest snapshot. Each
  now validates the decoded container and fails open as its surrounding state
  handling intends. Regressions cover a non-object token cache, a real legacy
  quiet-queue list plus a scalar, non-object search activity, and non-object
  weekly digest state.
- The weekly-spend regression exposed a separate resource bug on Windows:
  `with sqlite3.connect(...)` commits/rolls back but does not close a SQLite
  connection, leaving the digest's spend DB locked after return. Replaced it
  with the file's established `closing(sqlite3.connect(...))` pattern; the test
  proves its temporary DB can be deleted immediately after the read.
- Fixed two global-deadline violations. `_deepseek_alert_sanity_check()` and
  `_deepseek_second_opinion()` checked whether time remained, discarded the
  computed bound, then made a default 15-second call. Both now pass the actual
  remaining time (capped at 15 seconds) into the text provider. Regressions
  prove 4.5-second and 1.75-second remaining windows reach the request helper.
