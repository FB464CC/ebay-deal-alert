2026-09-10 — implementation decision and edits in progress
- Fresh remote log totals: 706 rows; the nine exact delivered Vinted Longines/King-Seiko-targeted rows have discounts 78, 79, 79, 82, 88, 90, 93, 93, and 93; eight are medium-confidence. Both generic counterfeit keys are absent from every one, while the log does contain the golf-prefixed counterpart. A separate set of similarly cheap Vinted Longines rows was blocked as COUNTERFEIT specifically for implausible price. That is inconsistent counterfeit classification plus lost telemetry, not a uniform FX conversion failure.
- Vinted's adapter only normalizes a catalog row before the AI call; it cannot drop an AI response field. No platforms.py change is warranted. It reads raw `item.price.amount`, derives a buyer-protection delta from `total_item_price.amount`, and has no 10x or FX conversion path. It does default the normalized currency to USD, so the retained log cannot independently prove checkout currency, but the US host/shipping context and exact raw-price arithmetic give no evidence that $800 was converted to $80.
- Current checked-in code can only print its extreme warning at >=80%, so it cannot itself have produced an 78/79% warning in a pasted notification; that would have come from a different deployed revision/path. The old threshold nevertheless left 70-79%-off watches at Priority 5 because the urgency rule already uses 70%.
- Chosen behavior: lower the watch review threshold to 70%, aligning it with the existing Priority-5 Steal boundary and covering the reported 74% as well as the fresh 78/79% rows. This is deliberately NOT a blanket suppression. A watch at that threshold is Priority 5 only if the AI explicitly returned `counterfeit_suspected: false` AND price confidence is high. An unknown/null/malformed verdict, or any non-high confidence, is still delivered but as a Priority-2 `WATCH REVIEW` with an explicit low-priority warning; an explicit true remains blocked by the existing quality gate. This removes the lock-screen "Steal" treatment for the real noisy pattern while preserving access to a genuinely vetted rare steal.
- Edited ebay_deal_alert.py only: strengthened the watch prompt; preserved strict True/False/None parsing immediately after the AI call; added explicit watch-AI telemetry and persisted both counterfeit fields including null; centralized watch extreme-discount classification; changed urgency and watch notification wording/title accordingly.
