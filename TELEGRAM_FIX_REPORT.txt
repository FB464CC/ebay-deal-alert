Changes made
- Extended metadata parsing to recognize schema.org itemprop attributes on meta elements and on ordinary elements such as eBay price spans. Nested itemprop tags are scanned independently so an outer Offer element cannot hide a price span.
- Extended numeric price normalization to accept marketplace-formatted values such as `US $450.00` while still rejecting strings that are not solely a price.
- Added `price` and `pricecurrency` as structured metadata fallbacks after the existing product/OG keys; structured asking price continues to win over ambiguous dollar amounts in seller text.
- Centralized replied-message text extraction (`text` or `caption`) and used it both to identify bot replies and to build the DeepSeek follow-up prompt.
- Added Node-backed webhook integration coverage proving that a plain-text reply to this bot sends both the prior analysis and the new question to DeepSeek in plain-text mode, then replies to the current Telegram message. Added equivalent caption-context coverage and both itemprop price variants.
- Targeted post-fix check: 9 passed, 30 deselected, 6 subtests passed (`python -m pytest test_web_api.py -q -k "price or reply_to_own_bot or meta_attributes"`).

Reviewed but not changed
- A photo-only follow-up is explicitly acknowledged but not vision-analyzed (final lines 640-647); supporting that correctly requires Telegram getFile/download handling and deciding whether to re-fetch the original listing photos, which is a larger feature than these two bug fixes. Captioned follow-up information is handled.
- Conversation context intentionally relies on Telegram reply_to_message because this project has no keyed per-chat store. A new message that is not sent with Telegram's Reply action therefore remains a fresh request. Persisting implicit chat history would require a storage/lifetime/privacy design, so it was not added speculatively.
- telegramSend does not inspect Telegram's HTTP response status. Changing that alone could turn a send failure into webhook retries and duplicate paid AI calls, so this reliability behavior was flagged rather than changed without a retry/idempotency design.
