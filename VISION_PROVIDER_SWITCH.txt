Checkpoint 2 - end-to-end batching and router audit
- _paid_ai_budget_snapshot() reconciles the durable paid ledger and reports
  whether the next DeepSeek reservation would exceed the monthly cap.
  _record_paid_ai_budget_exhaustion() copies that structured snapshot into
  process state so the run can notify and classify a no-result consistently.
- Before this change, run() enabled free_fallback_batching only when DeepSeek
  was configured primary, GEMINI_BATCH_SIZE was greater than one, and a
  pre-attempt paid snapshot was already exhausted. This intentionally avoided
  changing exceptional one-candidate fallbacks while paid DeepSeek remained
  available.
- Once enabled, each current candidate completes the ordinary lane-budget,
  detail, and late hard-fail gates. It is prepared as the batch anchor, then
  eligible adjacent candidates from the same counter lane are prepared up to
  GEMINI_BATCH_SIZE. Future eBay candidates receive the same detail fetch and
  late hard-fail gate before inclusion. Exact-ID results are stored in
  prefetched_gemini_results and consumed on those candidates' normal loop
  turns; malformed/missing results remain None and fail closed.
- _call_photo_check() routes to the configured provider first. In Gemini mode
  it calls Gemini first and, on an exception or no result, calls DeepSeek with
  its own deadline-clamped timeout. Successful Gemini results never spend a
  paid fallback. Batched request failures fail closed for all affected
  candidates; they cannot alert without an AI verdict.
- Important correction to the task's throughput premise: GEMINI_CALL_LIMIT is
  currently charged once per candidate outcome, including a later candidate
  consuming a prefetched result. The predecessor report explicitly preserved
  that behavior. Therefore at GEMINI_CALL_LIMIT=12 and GEMINI_BATCH_SIZE=3,
  twelve fully eligible candidates use four Gemini HTTP requests when batched
  versus twelve HTTP requests when unbatched; both modes vet at most twelve
  shared-lane candidates per run. A 36-candidate run would require changing
  the counter and the protected 12-slot golf/poker fairness semantics, which
  is outside this surgical provider switch and would violate the requirement
  to preserve today's DeepSeek behavior.
