Checkpoint 3 - concrete delivered broken-watch reproduction
- Production delivered eBay item `v1|287464714587|0` at 2026-09-13T22:22:43Z:
  `Oris Gold Filled 10 Microns 17 Jewels Mesh Band Square Face Watch W/ Box
  1960s C`, landed $42.40, AI resale $100, Great Deal 58%, medium confidence.
  Its recorded AI summary says there are no obvious major flaws.
- The live eBay item page's structured condition is `For parts or not working`,
  whose eBay definition explicitly says nonfunctional/defective/requires repair
  or is missing essential components. The production log has neither
  ebay_condition nor ebay_condition_id for this alert.
- Code-path trace proves this is a third mechanism, not a regression in the
  settled official Browse condition gate. Browse search results retain condition
  and exclude conditionId 7000. `ebay_scrape.py` only extracts id/title/price/
  image (plus auction countdown). The later item-description enrichment in
  `run()` is guarded by `if not listing.get("platform")`, so it deliberately
  skips `platform="ebay_scraped"`. Consequently this real listing reached AI and
  delivery with neither structured condition nor description. Image review
  cannot establish whether a mechanical movement runs.
- The bounded fix is to let the existing item-detail request return description
  plus condition/conditionId, run it for official and scraped eBay rows, merge
  those fields before the paid call, and re-run the existing structured/text
  condition gate. No scraper-file edit is necessary.

Checkpoint 4 - full pre-AI layer audit and targeted backtest design
- Read every pre-AI path used by enabled config categories: marketplace/title
  relevance and exclusions; relist/size/width/fitted-shirt/max-price/suit-size
  gates; watch identity/authenticity/lot gates; golf wrong-item detection;
  universal gender/pet/packaging/counterfeit/structured-condition/text-condition
  scoring; apparel brand/fabric/logo checks; staleness; repeat no-price cap;
  sold-comparable and seller-feedback scoring; category fairness; and the final
  poker, golf, watches, school, knitwear, tailoring, and default category gates.
- Current numeric `_pretriage_score` is not a true steal-likelihood filter: it
  awards at most sold-comps and seller-feedback points, then scheduling fairness
  sends many candidates to AI whose final category gate rejects deterministic
  facts already visible in title/description. The observed 0.55%-5.16% terminal
  yield is the direct production measure of that looseness.
- Replayed all seven-day terminal AI rows through current title-only prefilters,
  then evaluated only deterministic incremental rules. Proposed golf title rules
  remove explicit left-handed-only items and title-identifiable blocklisted
  brands before AI. The broad historical union was 76/1,126 current survivors
  (6.75%) and removed 0/19 delivered golf alerts; implementation will use the
  safer non-conflicting handedness form and the existing brand parser, then
  report the exact final count.
- Proposed poker rules require a chip identity (or a settled premium maker),
  reject an explicit count below the already-settled 100-chip minimum, reject
  explicitly ineligible plastic/composite/metal-core construction, and reject
  explicit samples/empty storage. The broad candidate union was 260/724 current
  survivors (35.91%) and removed 0/4 delivered poker alerts. Implementation will
  avoid speculative carousel/caddy rejection and report the narrower exact
  result.
- Proposed watch rules add explicit nonfunctional wording missed by the generic
  list (`not running`, `does not run`, `nonfunctional`, etc.) and a mathematically
  impossible margin check: if landed cost already exceeds half the model's
  configured maximum resale band, the existing >=50%-under gate cannot ever
  deliver it after resale clamping. Both had zero overlap with 21 delivered rows.
- Scraper-coverage hypothesis explicitly refuted after checking the source
  objects rather than relying on a derived summary: all 18 poker searches do
  carry category_id `166570`, and both official Browse and the supplementary
  scraper receive it. eBay's current primary category page independently
  confirms 166570 is Poker Chips. There is no current category-scope defect and
  no category/search configuration change is warranted.

Checkpoint 5 - implemented rules and exact historical backtest
- Golf: extended the existing title wrong-item gate with two facts that its
  final AI gate already rejects: an unambiguous left-handed-only title (not a
  stand bag, and no conflicting RH/right-handed signal) and a blocklisted brand
  recognized by the existing conservative brand-segment parser. This preserves
  Tour Edge Exotics and ambiguous/mixed-brand titles for vision.
- Poker: added a deterministic pre-AI text gate that (1) requires poker-chip/
  poker-set/casino-set identity or one of the already-targeted collector makers,
  (2) rejects a title's explicit count below the settled 100-chip minimum,
  (3) rejects only explicit chip construction known to be out of scope
  (plastic/ABS/clay-composite/metal-core), and (4) rejects samples or explicitly
  empty storage. Ambiguous sets, counts, materials, caddies, and cases still go
  to vision. Added POKER_PRETRIAGE_REJECT telemetry.
- Watches: added unequivocal function-language rejection for `not running`,
  `does not run/wind/tick`, nonfunctional, stopped working, not keeping time,
  and dead movement. Added a pre-AI mathematical margin gate only where a known
  configured brand band exists: landed cost above half its high ceiling cannot
  possibly reach the existing >=50%-under final bar after the existing ceiling
  clamp. The same helper is a final-delivery backstop.
- Scraped eBay fix: the already-budgeted `/item/{item_id}` request now returns
  description plus normalized condition/conditionId. `run()` performs it for
  both official and `ebay_scraped` rows, merges evidence, then repeats structured
  condition and category text gates before vision. The exact delivered Oris
  reproduction now logs CONDITION_REJECT with conditionId 7000, makes zero AI
  calls, and sends zero alerts.
- Final exact seven-day replay over terminal AI rows (provider identity is not
  logged, so paid vs fallback cannot honestly be separated):
  * golf: 46/1,157 calls avoided (3.98%), 0/19 deliveries removed; projected
    precision 1.64% -> 1.71%.
  * poker: 135/724 avoided (18.65%), comprising 61 identity noise rows plus
    explicit sub-100 counts, 12 explicit construction failures, and 2 samples;
    0/4 deliveries removed; projected precision 0.55% -> 0.68%.
  * watches: 6/407 avoided (1.47%: five explicit nonfunctional titles and one
    impossible configured-band margin), 0/21 deliveries removed; projected
    precision 5.16% -> 5.24%. The Oris conditionId fix is additional because
    that evidence was absent from the historical log and came from the live
    item-detail reproduction.
  * combined priority categories: 187/2,288 historical AI reviews avoided
    (8.17%), with 0/44 delivered alerts removed; projected terminal precision
    1.92% -> 2.09%.
- This does not honestly achieve a 99% pre-AI rejection rate. It is the largest

  improvement; golf's low alert yield remains primarily the monthly-budget
  outage plus a genuinely selective >=50%-under final bar, not a newly found
  golf coverage defect.
